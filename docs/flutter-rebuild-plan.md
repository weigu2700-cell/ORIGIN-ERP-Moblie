# Flutter 移动端重构准备稿

状态：准备与设计阶段，尚未创建 Flutter 工程。现有 uni-app 功能暂停扩建。

## 已确认方向

- 发布目标改为 **Android + iOS 的统一移动 App**。
- 扫码、库存、领料、报工与出入库等原 PDA 作业能力直接融入移动 App，使用相同账号、权限、业务页面和服务端接口。
- 安卓 PDA 作为可能使用该 App 的设备，厂商扫描头按具体设备后续适配，不单独建立一套 PDA 产品。
- 组织融入登录表单、页面顶部和个人账户信息，不再占用独立的工作台卡片或页面区块。
- AI 助手拥有独立入口、会话列表页和对话详情页；会话列表是正式页面，不以聊天页抽屉代替。
- 先确定导航、页面职责和状态，再建立 Flutter 工程及实现功能。

H5、微信小程序和桌面端不属于本次已确认的发布目标。原 uni-app 版本保留为迁移期间的功能参考；Web 管理端与现有服务端继续使用。

### 必须先审的页面原型

1. 登录：组织融入表单，错误提示与软键盘状态可达。
2. 工作台：组织、仓库、待办各有明确位置，减少重复入口和大块提示。
3. 库存列表 → 扫码 → 查询结果：确认查询目标，取消不改变原条件。
4. 报工登记 → 单据详情：填写与审批动作分开，数量及提交结果可核对。
5. AI 会话列表 → 对话详情：返回列表保留阅读与列表位置，新建对话有明确入口。
6. 我的 → 切换组织 → 重新登录：说明未提交内容的影响，完成后清理原身份状态。

页面原型同时覆盖窄屏、大字体和键盘打开状态。保持现有品牌色与业务术语，组件、间距、字号和触控尺寸先形成统一规范。

### 扫码与原 PDA 能力

- Android 和 iOS 首先具备手机相机扫码、手工输入、粘贴和外接键盘/扫码输入。
- 扫码入口存在于实际作业页面；识别先得到编码，再由当前业务明确查询或选择，不自动审批或出入库。
- 相机权限拒绝、重复识别、退出/后台释放、前导零和长编码都纳入两端验收。
- 如采用厂商广播或 SDK 读取工业扫描头，单独实现设备适配层；设备型号未确定之前不承诺专用扫描头兼容。
- 首版按在线作业与弱网恢复设计。完整离线制单、库存冲突合并和后台同步属于独立能力。

## 技术边界

参考 Flutter 官方 [架构指南](https://docs.flutter.dev/app-architecture/guide)，按页面/ViewModel、Repository、API/平台服务分离职责。跨业务的会话、组织、权限、请求取消和错误模型统一维护；具体状态库、路由库和插件版本在技术验证后锁定。

- 服务端维持现有 REST 与 SSE；App 不直连数据库，不保管模型密钥。
- ID 始终使用字符串；数量按既有十进制精度规则处理，写入前后均以服务端校验为准。
- Token 使用移动端安全存储，组织/用户变更形成新的会话边界，取消旧请求、AI 流、旧确认弹窗与读写回调。
- 最近组织仅保存必要显示信息；业务数据、仓库与会话不能在相同用户 ID 的不同组织之间复用。
- 当前 multi 正式业务门禁继续有效，Flutter 登录成功不等于可以绕过 `businessAvailable=false`。
- 写入超时、断网或退后台时区分「尚未提交」与「结果未知」；未知结果先核对单据，不自动重放。
- AI 保留后端 `CONTENT/TITLE/ACTION/ERROR` 契约，覆盖 UTF-8 分片、停止、断流和身份变化；只在明确确认并重新核对权限后执行业务动作。
- 平台差异集中在相机、权限、安全存储、扫码设备和发布配置，业务状态保持一致。

建议 Flutter 与旧 uni-app 并行保留，迁移完成前原版本只做必要维护。工程位置有两种可评估方式：

| 方式                      | 取舍                                                    |
| ------------------------- | ------------------------------------------------------- |
| 独立 Flutter 仓库（建议） | 构建、发布和依赖清楚；需要维护与服务端的版本配套关系    |
| 当前仓库的重构分支        | 保留仓库入口；切换期间需明确 Node 与 Flutter 的构建边界 |

工程建立前再确定仓库位置、Android applicationId、iOS Bundle ID、测试/生产环境及分发方式。没有创建新远端仓库或修改现有发布入口。

当前本机 PATH 中未找到 `flutter`、`dart`；`adb` 可用。这不排除其他目录已安装 SDK，正式开工前需要检查工具链。iOS 构建与发布还需准备 Xcode、签名和对应分发配置，见 [iOS 发布](https://docs.flutter.dev/deployment/ios) 与 [Android 发布](https://docs.flutter.dev/deployment/android)。目标系统最低版本对照所选 SDK 的 [官方支持平台](https://docs.flutter.dev/reference/supported-platforms) 及实际设备清单确定。
