# 移动端生产作业闭环

## 本轮范围与入口

已确认本轮优先补齐生产报工及权限、防重复提交。现有 uni-app + Wot、中文文案和浅色制造业工作台样式保持一致；不新增商城或多租户能力。

服务目录 → 生产报工 → 登记/查询/查看详情；生产中的订单详情也可以直接进入登记报工。
流程：生产中订单 → 报工草稿 → 审批 → 完成报工 → 成品入库草稿 → 审批 → 确认入库。
完成报工只生成入库单，实际库存增加发生在 `/inv/finish-warehousing/{id}/warehouse`。
旧移动端“成品入库”错误调用报工接口的问题已修正；旧详情链接不再将报工 ID 当作入库单 ID，而是返回真实入库列表。

## 交互与数据契约

- 作业人员选择生产中订单，物料取订单详情；有固定目标仓库时沿用该仓库，否则从已授权的启用仓库中选择。仓库支持继续加载，订单搜索显示匹配数并支持缩小单号范围。
- 报工、合格、报废数量非负，报工数量大于零，合格与报废之和不超过报工数量。最多四位小数，使用字符串传输和整数单位校验，避免浮点误差；累计报工、订单状态、物料和仓库最终由后端校验。
- 表单失败保留输入，成功进入明确的已提交状态，不能反复点击再次创建。超时、断网或服务端故障导致结果未知时，不自动重试，先核对报工记录。
- 报工与入库动作由各自的状态及精确权限码控制。详情操作先确认影响、重新获取单据状态，再执行一次写请求。重复点击从准备阶段即加锁；离线、权限变化、状态变化时停止。
- 表单只负责创建草稿，不把登记等同于审批；报工详情支持审批、取消、完成、驳回，入库详情支持审批、取消草稿和确认入库。后端权限仍为最终约束。
- 成品入库查询使用独立枚举名称 DRAFT/APPROVED/WAREHOUSED/CANCEL，响应中的状态仍是数字；不会混用报工状态。
- 登录校验失败、权限不足、空列表、加载、读失败重试、写失败、结果未知、成功均有明确说明和下一步。服务目录入口按列表权限开放，订单详情的登记入口按报工权限开放。

## 布局与可访问性

读取本地 `uni.scss`、订单/领料/入库页面、OfflineBanner、useListState、服务目录及后端 DTO；不重新设计登录和工作台。
复用现有品牌色 #245b78、底色 #eef3f5、正文 #162631、边框 #d6e0e6；共享样式放在 `src/shared/styles/production.scss`。

报工表单信息顺序为订单 → 目标仓库 → 三种数量 → 备注 → 提交；详情为单号/状态 → 订单/仓库/数量 → 操作影响 → 动作。输入区与按钮最小高度 48px，基础字号 16px，标签不靠占位符代替，状态与错误都用文字表达。
页面在 320/390/430px 单列排列，按钮和状态筛选允许换行，长单号折行，底部保留安全区；600px 以上限制阅读宽度。内容区自然滚动，提交按钮位于表单末尾，键盘打开时可滚动到达，避免固定底栏遮住输入。没有新增动效、暗色主题或 RTL 支持。

参考：[W3C 触控目标尺寸](https://www.w3.org/WAI/WCAG22/Understanding/target-size-minimum.html)、[WAI 表单结果与错误提示](https://www.w3.org/WAI/tutorials/forms/notifications/)。采用现有组件与业务状态，不引入额外设计系统。

## 验证与边界

执行 `npm run test:run`、`npm run type-check`、`npm run lint`、`npm run build:h5`、`npm run build:mp-weixin`。
回归覆盖数量/小数/ID、状态与目标仓库、真正入库端点、权限/离线/重复点击/取消确认、原生网络判断及监听释放。

真机上线前核对：在生产订单登记报工，审批并完成，确认生成实际入库单，再审批和入库；核对库存只在最后一步增加、弱网结果未知时不重复提交、员工与审核人权限分离；使用 320px 等效宽度与大字体、软键盘检查全部字段、错误提示和主按钮可达性。
前端提交锁不能替代后端跨设备幂等和并发约束。现有扫码文件属于工作区先前改动，本轮没有修改扫码行为。
