# 移动工作空间 · 业务需求 V1

日期：2026-11-03。状态：设计评审基线。已确认产品方向与本轮设计提案分开说明；样例截图不构成接口或业务能力承诺。

## 1. 产品定位与使用场景

为中小制造团队提供统一移动工作入口：知道当前待办、找到业务单据、在现场完成作业、通过 AI 查询业务。整体体验参考企业移动工作空间，业务深度围绕生产与仓储闭环，保持轻量。

| 主要角色 | 现场任务 | 页面重点 |
| --- | --- | --- |
| 生产作业人员 | 找生产订单、查看领料、登记报工 | 一眼辨认物料/状态/进度；数量快速输入；失败不丢内容 |
| 仓库人员 | 扫码查料、核对领料、采购/成品入库、销售出库 | 编码、仓库、数量一致；核对与过账分开；结果可追溯 |
| 主管/有审批权限的人员 | 查看通知、审核单据、核对生产进展 | 单据状态清楚；权限精确；审批不混同仓库执行 |

角色可重叠，能力由服务端授权决定，不能把角色名称写死为权限。工作台的岗位排序、常用应用配置与个人待办聚合为拟建设能力，需核对数据来源。

首版在线作业，考虑弱网和中断恢复；完整离线制单、冲突合并、后台自动过账不在首版范围。

## 2. 范围

**用户已确认**：Android/iOS 统一 App；扫码/PDA 作业融入 App；组织融入身份与页面；AI 独立列表与详情；生产闭环优先；先设计后 Flutter。

**当前提案**：消息/工作台/AI助手/我的四个主入口，业务应用内聚到工作台。消息仅做业务通知，不引入即时聊天。

| 模块 | 首版目标 | 后续或不承诺 |
| --- | --- | --- |
| 身份与组织 | 登录、组织解析/最近使用、失效处理、权限与组织切换 | 公开企业名录、自助注册、无感跨组织切换 |
| 工作空间 | 常用应用、业务待办入口、消息收件箱 | 低代码门户、拖拽搭建、应用商店、IM/文档/会议套件 |
| 生产 | 订单列表/详情、领料、报工、相关成品入库 | 设备联网、工位排产、工时计件等新业务模型 |
| 仓储 | 库存、仓库筛选、采购入库、成品入库、销售出库 | 库位/托盘/波次作业、离线库存同步 |
| 扫码 | 相机、手工输入、通用外接输入；返回调用页面 | 未选型厂商 SDK/系统广播的兼容承诺 |
| AI | 会话列表、历史、新对话、流式回答、停止、归档、确认动作 | 语音、文件上传、RAG、任意单据自动执行 |

## 3. 核心业务链路

### 3.1 身份与组织

登录由组织、账号、密码构成一个连续表单。默认组织按配置解析；最近组织仅记录成功使用过的必要显示信息，不能提供未授权的全量组织浏览。

当前组织在页头、详情副标题或账户信息行体现，不重复占用工作内容。切换先提示未提交内容影响，再退出重登；业务数据、仓库、会话、确认令牌和异步回调不能沿用旧身份。

单租户可用业务与多租户建设进度分开：现有 multi 门禁 `businessAvailable=false` 有效时，应展示可解释的不可用状态，不能进入写操作或 AI 假装可用。

### 3.2 消息与工作台

- 消息：类型图标、事件标题、时间、单据说明、状态；点开进入对应单据，权限不足时给出说明。
- 已读状态与业务状态独立。全部已读不等于处理全部待办；重复事件不得在一次生产操作后变成二十多条重复通知。
- 正式实现需要核对通知事件标识、重连补偿、订阅释放、前端去重及读状态来源，不凭 UI 去重掩盖服务端重复发布。
- 工作台：岗位常用应用与待办入口优先，展示数量需明确统计范围；没有个人分配数据时，不把全企业任务称为“我的任务”。
- 待办默认只包含当前账号有权查看/执行的单据；点击回查最新状态，过期通知不提供已失效动作。

### 3.3 生产订单 → 领料 → 报工 → 成品入库

1. 订单列表展示物料、单号、状态、计划/完成数量；详情展示计划日期、仓库及相关业务。
2. 打开已审批领料单，核对一个物料、仓库和待领数量；扫码只验证编码，不修改数量或立即扣库存。
3. 领料确认执行后回查单据与库存流水。当前契约是 `POST /prd/picking/confirm?id=...`，不凭 UI 新增扫描数量参数。
4. 从生产中订单登记报工，输入本次报工、合格、报废数量和备注，保存为草稿。
5. 审批与完成报工由对应权限/状态执行；不能把“保存”按钮当作一键审批完成。
6. 根据实际生成的成品入库单，由仓库核对合格数量和目标仓库后办理入库。确认入库才增加库存。

现有生产接口包括订单开始/下达/完成/取消，领料审批/确认，以及报工新增/审批/驳回/取消/完成。设计 V1 没有把所有动作绘为页面，正式迁移需逐项核对权限、状态与结果。

数量使用十进制语义，最多四位小数；本次报工量大于零，合格和报废非负且合计不得超过报工量。前后端校验一致，失败保留输入。ID 全程字符串，避免数值精度损失。

### 3.4 库存与其他仓储执行

库存按物料和仓库查找，在库、预留、可用量分别呈现，可用 = 在库 − 预留。加载失败不能显示成库存为零。

采购入库审批与仓库上架、销售单确认与销售出库执行分别处理。当前图稿是统一结构提案，具体批量明细、执行前置状态及过账接口还需联调，不因三个页面长得相同就共用错误的状态机。

扫码保留前导零与长编码；权限拒绝时仍可手工输入。识别后先匹配当前业务目标，多结果要选择；取消回到原任务，不能改变仓库或单据。重复识别只进入一次核对，不自动发起写请求。

### 3.5 AI 助手

入口先进入会话列表，提供新建、进行中/归档与历史访问。列表只使用实际字段：标题、更新时间、状态；不依赖未提供的内容摘要。

详情支持用户输入、流式文本、业务数据表格、相关单据跳转、停止和历史恢复。停止保留已收到内容，失败后先核对历史，避免把同一用户问题重复发送。归档后只读，新问题进入新会话。

| 已有服务契约 | 用途 |
| --- | --- |
| `GET/POST /ai/conversation` | 列表/创建 |
| `GET /ai/conversation/{id}` | 当前身份会话 |
| `PUT /ai/conversation/{id}/archive` | 归档 |
| `GET /ai/message/{id}` | 会话历史，参数含义以实际控制器为准 |
| `POST /ai/assistant/chat/stream` | SSE：CONTENT / TITLE / ACTION / ERROR |
| `POST /ai/action/{token}/execute` | 用户确认后执行动作 |

当前可复用的是库存/生产/采购/销售/本人通知等受权限控制的查询，以及采购订单审核确认动作。模型不能自行绕过权限、直接出入库或操作任意模块。ACTION 提案需要展示目标单据与影响，用户确认后服务端重新校验；令牌失效、权限变化、状态变化应明确告知。

## 4. 跨模块验收

| 项目 | 验收标准 |
| --- | --- |
| 身份隔离 | 切组织、退出或登录失效后，旧请求/AI 流/弹窗不能更新新身份页面 |
| 写入与弱网 | 提交期间防重复触发；执行结果未知先回查，不能自动重放；失败保留输入 |
| 权限与状态 | 列表、详情、主动作分别按精确权限处理；后端校验最终生效 |
| 查询恢复 | 返回列表保留组织、筛选和阅读位置；错误/空状态分别表达 |
| 通知一致性 | 同一事件不会因重复订阅或重连反复弹出；已读不改变业务待办 |
| 手机适配 | 320/390/430 布局、大字体、软键盘与安全区可达；两端返回行为一致可预测 |
| 扫码 | 相机拒绝、重复识别、错误编码、后台恢复、取消与外接输入均有路径 |
| AI | 历史/新建/归档、停止/断流/UTF-8 分片、动作确认/失败/组织变化均验收 |

## 5. 开发前需补的契约与页面

- 工作台待办聚合与计数：统计对象、权限、分页、是否真正存在个人分配；必要时新增服务端聚合接口。
- 通知：真实事件类型、单据跳转、已读/全部已读、分页与去重标识，核对现有服务是否足够。
- 会话：现有列表返回集合，正式分页/搜索/排序和大列表性能方案需补设计，不能假设已有。
- 单据：补生产领料/报工/采购入库/成品入库/销售出库的完整列表和状态页；补报工详情与审批操作规范。
- 确认与恢复：界定每个写接口的状态校验、幂等策略、未知结果回查路径；新增制单若无请求标识则需后端补齐。
- 平台与交付：Flutter 仓库位置、标识、最低系统版本、测试/生产环境、签名与分发方式待工程阶段确认。
