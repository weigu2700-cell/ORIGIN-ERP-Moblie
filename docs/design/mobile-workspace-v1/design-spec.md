# 移动工作空间 · 设计说明 V1

2026-11-03。设计评审稿，尚未确认。范围与业务约束以 [业务需求](BUSINESS_REQUIREMENTS.md) 为准，实施状态见 [交接](HANDOFF.md)。

## 设计目标

把应用入口、业务通知和现场作业整合为一个轻量工作空间。面向在现场拿手机找单、核对、扫码、录入数量的生产与仓库人员；主管在同一身份体系下处理授权的单据。页面优先回答“在哪个组织、哪张单据、当前什么状态、下一步能做什么”。

当前设计在结构上借鉴企业协作产品，在执行步骤上借鉴仓储平台；没有复制其品牌、营销界面或引入完整办公套件。

## 信息架构与关键决策

**提案：消息 / 工作台 / AI助手 / 我的，登录后默认工作台。**

- 消息承载业务收件箱；工作台承载应用与任务，减少两个应用目录的重复。
- 全部应用属于工作台二级页面，生产、仓储、采购、销售按领域归类；正式入口按权限开放。
- 当前组织融入页头；详情可在标题副行体现，切换入口只在稳定位置出现，不增加大型组织卡片。
- 业务详情围绕一个对象，顶部辨认单号/状态/物料，中间核对数量和仓库，底部保留主要动作。
- AI 先列表后详情，有自己的导航栈；助手回答以正文与表格呈现，用户消息弱底色，业务动作另行确认。
- 扫码为共享能力，由当前业务调用并返回编码/选择结果，保留输入替代路径。

这套架构偏重生产业务协作，取舍是暂不提供人员聊天、文档、日历等协作套件功能。底部四入口仍需用户评审；若实际消息密度不足，应重新评估其一级入口价值。

## 消息列表间距修正

- 根因：`.phone button` 通用重置覆盖了 `.notification-row` 的 padding；同样影响了其他按钮型卡片。
- 修正通用重置优先级，让具体组件控制内边距；消息行明确四边 20px，图文间隔 12px。
- 图标 40px；标题与时间顶对齐，时间不压缩，摘要占独立段落并自然换行，状态置于摘要下方。
- 标题 15px、摘要 13px、时间/状态 11px 为本轮初稿；摘要字重恢复正常。最终需按可读性和设备字体继续校准。
- 行高由内容撑开，不用固定高度裁字；窄屏/大字体允许行高增加和列表滚动。

## 视觉规范（提案 token）

| 角色 | 当前值 | 使用方式 |
| --- | --- | --- |
| 主文字 | `#1C2536` | 页面标题、对象名称、核心数量 |
| 品牌/主动作 | `#2C60E8` | 主按钮、当前标签、选中导航 |
| 画布/表面 | `#F5F6F9` / `#FFFFFF` | 用轻分区建立层次，避免大面积彩色卡片 |
| 分隔线 | `#E7EAF0` | 列表和信息组边界 |
| 消息摘要/时间 | `#536279` / `#66758A` | 保证正文比装饰信息更容易阅读 |
| 语义色 | 绿成功、琥珀待办、红异常 | 同时配文本和图标，不仅依赖颜色 |
| 间距 | 4 / 8 / 12 / 16 / 20 / 24 / 32 | 页面左右默认20，紧凑结构内部12–16 |
| 字体 | 平台系统字体 | 标题约25/23，正文14–16，辅助11–13；关键字段不降为小字 |
| 圆角 | 控件8–12 | 表达分组；避免每段内容都包装为卡片 |

Flutter 中以语义 token 落地，不机械复制浏览器 px。截图内设备圆角、系统状态栏和底部手势条是评审外框，正式 App 应使用真实系统安全区。

## 交互约定

| 交互 | 正式产品应有的行为 |
| --- | --- |
| 主导航与返回 | 切主入口保留各栈，详情返回保留列表位置；不能把退出编辑伪装成普通切页 |
| 组织切换 | 说明未提交内容影响，重新登录并清理旧身份；不能直接切换变量继续写业务 |
| 扫码 | 识别后核对当前对象，重复识别去重；取消/拒绝相机可返回或手输 |
| 数量表单 | 规则就地提示，错误聚焦并保留输入；键盘不遮挡当前字段和保存路径 |
| 单据写入 | 核对单据、仓库、数量与影响，显式确认；提交中锁定，未知结果先回查 |
| 通知阅读 | 阅读只改变已读状态；进入单据回查权限与最新状态 |
| AI 输入与流 | 新建为空对话；发送显示真实问题；停止保留部分内容；不因返回或重连重复发送 |
| AI 执行动作 | 仅服务端提案可执行，确认前展示目标与影响；失效/权限改变时阻止执行 |

## 状态设计要求

| 状态 | 表现与恢复 |
| --- | --- |
| 首次加载 | 局部骨架、稳定栏位，避免页面跳动；不显示虚假零值 |
| 空数据/无搜索结果 | 说明当前条件，提供修改条件或返回路径 |
| 加载失败 | 就地说明，允许重试；保留已显示内容和筛选 |
| 离线/弱网 | 区分缓存可读与不可执行；不声称离线可过账 |
| 无权限 | 显示无法访问原因与返回路径；不让禁用态隐藏原因 |
| 身份失效/组织不可用 | 回到身份流程；组织业务未开放明确说明 |
| 提交中 | 阻止重复提交，保留对象/数量，避免重复弹层 |
| 结果未知 | 展示单据号与回查入口，不自动再次执行 |
| 成功 | 基于服务端确认，显示业务结果和下一步，避免只有 Toast |
| AI 停止/断流/归档 | 停止保留内容、断流核对历史、归档只读且可新建 |

原型右栏提供部分状态评审入口，不能据此推断上述状态全部已实现。

## 平台与无障碍

Android 与 iOS 保持业务结构一致，返回、权限弹窗、文字输入、相机和安全区遵循平台行为。普通字号下登录字段与主按钮应在常见视口内；软键盘或大字体导致空间不足时允许必要滚动，不能为“绝不滚动”裁掉操作。

实施目标：触控目标至少48逻辑像素；正文对比度至少4.5:1；非文本关键控件至少3:1；支持文本放大且不丢字段；为图标按钮、状态与错误提供语义标签。当前其他辅助文字和小按钮仍需按这些目标检查。

动效限于页面与确认反馈，不用弹跳或持续闪烁突出业务；尊重减少动态效果偏好。弹层需可返回/关闭、焦点限制在弹层内并在关闭后恢复到触发位置。正式产品应覆盖屏幕阅读器与外接键盘。

## 验证与下轮评审

当前检查聚焦静态设计，不是业务测试：三种尺寸检查主要内容容器无横向溢出；消息列表在各尺寸保持20px内边距和12px图文间隔；320宽、1.5倍字体允许正常纵向滚动。检查记录见 [QA](QA.md)。

下轮优先评审：工作台首屏是否体现岗位任务；消息列表密度与可读性；生产闭环中每一步的主动作；AI 列表与详情；然后补齐审批与恢复页面。用户确认后才进入 Flutter 实现。
