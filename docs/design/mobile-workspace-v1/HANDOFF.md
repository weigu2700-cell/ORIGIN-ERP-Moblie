## 实施时必须保留的业务约束

详见业务需求文档，重点是：

- 领料先核对再确认执行；当前一个领料单一个物料，没有库位、托盘或批量扫码过账。
- 保存报工草稿、审批/完成报工、成品入库是不同步骤；只有真实入库执行才增加库存。
- 数量最多四位小数，合格 + 报废不得超过报工量；ID 用字符串。
- AI 查询遵循现有权限；写操作必须明确确认，已存在的动作主要是采购订单审核。
- 结果未知先回查单据，不自动重试写操作；按钮锁定不能代替后端幂等/状态校验。
- 一租户一库、共用服务。当前 multi 的 `businessAvailable=false` 门禁不得因重构 UI 被绕过。
- 切组织要退出重登，清除旧组织缓存、AI 流、未确认动作及旧请求回调。
